## I. PROJECT CONTEXT

### A. What Are We Building?

We are adding a **Stock Financial Data Dashboard** to ECODATA. The new feature will:

1. ✅ Fetch financial reports from Vietnamese stock exchanges (HOSE, HNX, UpCOM)
2. ✅ Use Vnstock library to aggregate data from multiple sources (VCI, TCBS, DNSE, MayBank)
3. ✅ Implement intelligent caching (Redis) to avoid rate limiting
4. ✅ Use background jobs (Celery) for batch processing
5. ✅ Create a user-friendly dashboard (React Frontend)
6. ✅ Enforce membership restrictions (Free, Premium, Premium+)
7. ✅ Support CSV/Excel/Parquet export

### B. Why It Matters

**Problem:** Currently, ECODATA only has economic indicators. Users need Vietnamese stock financial data too.

**Solution:** Integrate Vnstock (existing open-source library) with smart rate limiting, caching, and fallback mechanisms.

**Result:** 2,500+ Vietnamese stocks with 4 financial reports each, available instantly, without hitting API rate limits.

## III. CRITICAL RULES (MUST FOLLOW)

### Rule 1: No Emoji in Console Output
**Why:** Windows terminal encoding breaks with emoji  
**Action:** Remove/replace ALL emoji from print(), logger, etc.

```python
# ❌ WRONG
print("✅ Database connected successfully")
logger.info("🚀 Starting API server")

# ✅ CORRECT
print("Database connected successfully")
logger.info("Starting API server")
```

### Rule 2: Verify Before Implementing

**Requirement:** Never code based on assumptions.

**Process:**
1. Read error message CAREFULLY (capture exact text)
2. Search codebase for similar patterns
3. Check Python type hints and validation
4. Test understanding on a small example first
5. THEN implement the full solution

**Example - WRONG:**
```python
# Task: Fix missing database column
# Action: Immediately add column to migration
# Result: Breaks production because schema mismatch
```

**Example - CORRECT:**
```python
# Task: Fix missing database column
# Step 1: Read error: "column 'updated_at' does not exist"
# Step 2: Check models/ directory for similar columns
# Step 3: Check existing migrations for pattern
# Step 4: Test: create test migration locally
# Step 5: Implement production migration properly
```

### Rule 3: No "Claude Code" Attribution in Commits

**Forbidden in commit messages:**
- "Used Claude Code to generate"
- "AI suggested this implementation"
- "Generated by AI"

**Allowed:**
- Technical details
- What changed and why
- Issue number (e.g., #42)

**Format:**
```
feat(stocks): add balance sheet API endpoint

- Added GET /api/stocks/{symbol}/balance-sheet endpoint
- Implemented 4-layer caching (Redis, DB, API, Fallback)
- Added rate limiting (60 req/min)
- Tests: 24/24 passing
```

### Rule 4: Single-Purpose Implementation Per Session

**Definition:** Implement ONE feature/fix per session, not multiple.

**Why:** Easier to test, debug, rollback

**Example - WRONG:**
```
Session includes:
  1. Add cache service
  2. Add rate limiter
  3. Fix database migration
  4. Deploy to VPS
  (TOO MUCH - 4 unrelated changes)
```

**Example - CORRECT:**
```
Session 0.1: Add cache service only
  - Tests pass
  - Commit: feat(cache): add Redis cache service
  
Session 0.2: Add rate limiter only
  - Tests pass
  - Commit: feat(rate_limiter): add rate limiting
```

### Rule 5: Test-First Documentation (CRITICAL)

**Definition:** Never write "Complete ✅" until tests actually pass.

**WRONG Process:**
```
1. Write code
2. Create wrap-up document claiming "Session #1 Complete ✅"
3. Later: Tests fail on VPS
4. Have to rewrite entire wrap-up document
5. Waste of time!
```

**CORRECT Process:**
```
1. Write code

3. Document: "Session #1 Status: Local tests passing 🔄"
```

#### Error Handling
```python
# ❌ WRONG - No specific exception handling
try:
    data = api.fetch(symbol)
except:
    return None

# ✅ CORRECT - Specific exceptions
try:
    data = api.fetch(symbol)
except ValueError as e:
    logger.error(f"Invalid symbol: {symbol} - {str(e)}")
    raise ValueError(f"Stock not found: {symbol}") from e
except TimeoutError as e:
    logger.warning(f"Timeout fetching {symbol}, using fallback")
    return await fallback_service.get_balance_sheet(symbol)
except Exception as e:
    logger.error(f"Unexpected error: {str(e)}", exc_info=True)
    raise
```

### FastAPI Code Standards

```python
# ✅ CORRECT - FastAPI endpoint template
from fastapi import APIRouter, HTTPException, Query, Depends
from pydantic import BaseModel
from typing import List, Optional

router = APIRouter(prefix="/api/stocks", tags=["stocks"])

class BalanceSheetRequest(BaseModel):
    """Request model for balance sheet"""
    symbol: str
    period: str = Query('year', regex='^(year|quarter)$')

class BalanceSheetResponse(BaseModel):
    """Response model"""
    status: str
    symbol: str
    source: str  # cache, api, fallback_TCBS
    data: List[dict]

@router.get(
    "/{symbol}/balance-sheet",
    response_model=BalanceSheetResponse,
    summary="Get balance sheet",
    tags=["financial-reports"]
)
async def get_balance_sheet(
    symbol: str,
    period: str = Query('year', regex='^(year|quarter)$'),
    current_user: User = Depends(get_current_user),
) -> BalanceSheetResponse:
    """
    Fetch balance sheet for a stock.
    
    - **symbol**: Stock ticker (e.g., ACB)
    - **period**: year or quarter
    
    Returns balance sheet data with source attribution.
    Automatically uses cache, falls back to API if needed.
    """
    try:
        # Check membership
        if current_user.membership == 'FREE' and period != 'year':
            raise HTTPException(
                status_code=403,
                detail="Free users can only view yearly reports"
            )
        
        # Fetch with smart service
        data, source = service.get_balance_sheet(symbol, period)
        
        return BalanceSheetResponse(
            status="success",
            symbol=symbol,
            source=source,
            data=data
        )
    
    except ValueError as e:
        raise HTTPException(status_code=404, detail=str(e))
    except TimeoutError:
        raise HTTPException(status_code=504, detail="API timeout")
    except Exception as e:
        logger.error(f"Error fetching balance sheet: {e}", exc_info=True)
        raise HTTPException(status_code=500, detail="Internal server error")
```

### Database Standards

```python
# ✅ CORRECT - SQLAlchemy model template
from sqlalchemy import Column, String, Integer, Float, Date, DateTime, Index, UniqueConstraint
from sqlalchemy.ext.declarative import declarative_base
from datetime import datetime

Base = declarative_base()

class BalanceSheet(Base):
    """Balance sheet data model"""
    __tablename__ = 'balance_sheets'
    
    id = Column(Integer, primary_key=True)
    stock_id = Column(Integer, ForeignKey('stocks.id'), nullable=False, index=True)
    symbol = Column(String(10), index=True)
    period = Column(String(10))  # 'year' or 'quarter'
    report_date = Column(Date, index=True)
    
    # Financial data
    current_assets = Column(Integer)
    non_current_assets = Column(Integer)
    total_assets = Column(Integer)
    current_liabilities = Column(Integer)
    non_current_liabilities = Column(Integer)
    total_liabilities = Column(Integer)
    total_equity = Column(Integer)
    
    # Metadata
    source = Column(String(20))  # VCI, TCBS, DNSE
    fetched_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
    
    # Indexes & Constraints
    __table_args__ = (
        UniqueConstraint('stock_id', 'period', 'report_date', name='uq_bs_symbol_period'),
        Index('idx_bs_symbol_period', 'symbol', 'period'),
    )
```

## VI. DEBUGGING TIPS

### If Code Doesn't Work

**Process:**
1. **Read the error VERY carefully**
   - Capture exact error message
   - Note line number and stack trace
   
2. **Check types**
   ```python
   # If error is "AttributeError: 'NoneType' has no attribute..."
   # It means something is None when it shouldn't be
   # Add type hints and check return values
   ```

3. **Add logging before the error**
   ```python
   logger.debug(f"Before suspicious line: {variable}")
   # suspicious line here
   logger.debug(f"After suspicious line: {variable}")
   ```

4. **Test with simple data first**
   ```python
   # Instead of testing with 100 stocks, test with 1
   result = service.get_balance_sheet('ACB')  # Just ACB
   # Then test with list of 5: ['ACB', 'VCB', 'TCB', 'BID', 'BVH']
   ```

5. **Check database state**
   ```bash
   # Connect to database
   psql -U finance_user -d finance_db
   
   # Check tables exist
   \dt
   
   # Check data
   SELECT COUNT(*) FROM balance_sheets;
   SELECT * FROM stocks LIMIT 5;
   ```

### Common Issues

**Redis connection error:**
```
Error: [Errno 111] Connection refused
Fix: docker-compose up -d redis (verify with redis-cli ping)
```

**PostgreSQL connection error:**
```
Error: could not connect to server
Fix: docker-compose up -d postgres (check .env credentials)
```

**Rate limit hit:**
```
Error: 429 Too Many Requests from VCI API
Fix: Verify rate limiter is active, check cache is working
```

**Cache not working:**
```
Test: redis-cli GET "balance_sheet:ACB:year" (should return data)
Fix: Check Redis is running, cache TTL is set
```
